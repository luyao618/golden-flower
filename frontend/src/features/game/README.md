# Package 2D: authoritative session state

Pure strict-TypeScript modules for the future session controller. They consume package 2A DTOs and `DecodedServerEvent`; they do not import React, Zustand, legacy stores/types, HTTP clients, sockets, storage, clocks or timers. A later Zustand adapter can own `GameSession` and dispatch `gameReducer` without duplicating its facts.

- `state.ts` defines the readonly snapshot, connection, turn eligibility, command lifecycle, scoped effects/reveals and redacted final receipt. `createGameSession` binds one game/player identity.
- `reducer.ts` replaces the snapshot for `game_state`/`game_started`, normalizing history by round. No other event edits players, chips, pot, actions, phase or current round. Decoded inputs are cloned before retention; previous states remain immutable.
- `selectors.ts` exposes the current actor, own player, round results, visible cards, action payments/disabled reasons, compare candidates, start availability and final receipt. Spending requires the server's action list. Cost/target guards only narrow that permission; they do not evaluate hands, award winnings, advance turns or enforce a client turn limit. Free off-turn peek is the existing WS exception.

`round_ended` upserts supplemental result presentation by round. Snapshot results take precedence over repeated events; each snapshot discards supplemental results and replaces all history facts. `player_chip_changes` is never applied. Private comparison reveals survive same-round snapshots, but clear on a new round, disconnect or connection generation. Ordinary opponent `hand` fields are never a visibility source. Own faces require `active_seen` in the current snapshot or a supplied authorized reveal; `cards_dealt` and action notifications alone reveal nothing. After a reload, a folded player's former seen status cannot be reconstructed and cards stay hidden unless explicitly revealed.

Effects have game, round, generation and monotonic local IDs, coalesce deal/settlement notifications, and cap the queue at 32. `effect.finished` only removes a matching token. It cannot clear the round or unlock a command. Snapshot restoration does not create replay animations.

## Controller contract for later packages

1. Create state for the selected identity. Allocate increasing connection generations across reconnects **and identity changes**; dispatch `connection.started`, then `connection.opened`. Every inbound message, send callback, timeout and effect completion carries its originating generation. Only open connections accept messages; old generations are ignored.
2. Decode with package 2A and dispatch `server.message`. Unknown events are ignored; invalid messages freeze eligibility until a valid viewer snapshot. A snapshot synchronizes facts, but ordinary actions still require an applicable subsequent `turn_changed`. Every replacement snapshot clears previous turn eligibility. The controller must not use cached turn notifications to fill that gap.
3. Allocate a monotonic local command ID and dispatch `command.requested` **before** sending. Only a transition to `sending` for that ID authorizes one send. Rejected reducer requests return the same state. IDs are local tokens, never added to the wire DTO. This package handles start and game actions; chat draft/delivery state belongs to its later package.
4. Dispatch `command.sent` after writing, `command.failed` with `not_sent` only if it definitely was not written, or `unknown` if delivery is ambiguous. `sending → awaiting_server → acknowledged` requires snapshot evidence: a newer round for start, confirmed seen status for peek, or an appended own action/target after an unchanged canonical action prefix. Peek needs no ActionRecord. Matching `player_acted` alone cannot prove progress or unlock controls.
5. Disconnect, ambiguous send, timeout or uncorrelated server error marks a pending command `uncertain`; a definitely unsent command is `rejected`. A new snapshot can acknowledge an uncertain command if it contains proof. An unchanged snapshot or unrelated progress cannot prove rejection. An unresolved uncertain command stays locked for later controller diagnosis; **never resend it automatically**. Terminal states remain observable until the next accepted request. Provider warnings do not reject wagers.
6. Bind effect completion to the full emitted token. Use `selectVisibleCards`, not raw DTO hands, for presentation. A new identity requires new state. `selectFinalReceipt(state, gameId)` exposes only IDs, names and chips from a final snapshot/event, never private cards; persistence and explicit HTTP `/end` handling remain later work.

The wire protocol has no revision/sequence/request IDs. The reducer cannot identify reordered same-generation snapshots or arbitrarily delayed unscoped events; it relies on ordered decoded delivery from the future controller. It deliberately prefers frozen controls to inferring a missing command outcome. Receipt scoping and card selectors are client correctness boundaries, not server access control.

## Exit-gate evidence

Tests consume 2A replay fixtures through the real decoder and include the full start/peek/call/raise/fold/compare/settlement sequence, all 2–6 seat counts, result-first and snapshot-first delivery, duplicate snapshots/results, next-hand effect completion, reconnects in blind/seen/AI/settled states, off-turn peek, participant/spectator comparison, supplied showdown cards, elimination and natural finish. Additional regressions cover immutable input ownership, full effect scope, malformed/unknown messages, opaque IDs, null fields, legal costs/targets/caps, stale send callbacks, uncertain delivery, canonical action matching and duplicate start-boundary snapshots.

TDD: both suites initially failed because the modules did not exist; start-boundary and reordered-action regressions were also observed failing before their fixes.
